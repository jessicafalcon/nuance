# ob-correctness

The product promise is a brief an account executive can trust: the quote is really
what the prospect said, the answer is the approved one, and nothing reaches a
prospect without a human. A change that produces a plausible brief but breaks one of
the invariants below is a **defect**, whatever the output looks like.

## The seven invariants

### 1. The guardrail is the only path from model output to a brief

Every detection passes `guardrail.check` before `brief.py` sees it. A detection is
kept only if all hold (brief §7.2):

- the quote appears in the transcript after normalizing whitespace, quote characters
  and case;
- `speaker == "prospect"`;
- `confidence >= config.min_confidence` (0.6 default);
- `theme_id` exists in `weaknesses.yaml`.

Normalization is one function used by both sides of the comparison. It never fuzzes
the match (no edit distance, no stemming): a paraphrase fails by design.

### 2. Nothing disappears silently

Every detection the model returns is logged, kept or not, with `kept` and a
`reject_reason` from the `RejectReason` enum. Rejections are counted by reason in the
`run` output and the eval report. A model answer that fails to parse is a recorded
failure for that transcript, not a crash of `run-all` and not a retry loop.

### 3. Human in the loop

- Nothing is ever sent to a prospect. The only outbound channel is the internal Slack
  webhook, or a file in `out/briefs/`.
- Every brief carries the footer "Draft answer — review before using."
- No auto-send, no email integration, no scheduling (brief §3, non-goals).

### 4. The follow-up is grounded

The follow-up call receives only the matching theme's `draft_answer`, `proof`,
`follow_up_angle` and the verbatim quote. Its prompt forbids facts, figures, customer
names and promises not in that input. `proof` values marked `[PLACEHOLDER]` stay
visibly placeholders in the draft.

### 5. Synthetic and neutral content

- No real planning vendor named anywhere: code, data, comments, docs, commits, PRs.
  The content guard blocks the known names by digest; the review agents check the rest.
- No real customer, person or review text. Transcripts and examples are synthetic;
  review language is paraphrased.
- Every theme in `weaknesses.yaml` has `status: draft` and its owner "to validate".

### 6. Honest evaluation

- Eval numbers are generated by `objection-brief eval` into `reports/eval_<model>.md`
  (committed), never typed. The README quotes them with the model and the date the
  report states (the latest `recorded_at` of the cache entries it read).
- Precision and recall are computed after the guardrail, against `labels.yaml`.
- The README says the test set is small and synthetic: the numbers show the method
  works, not real-world accuracy.
- Price constants in `config.py` carry "verify against Anthropic's pricing page" and
  the date checked.

### 7. Every model call is replayable

- Calls go through `llm.call_model()` and its cache in `data/llm_cache/` (brief §7.6).
  The key covers every input that changes the answer: model, prompt version, system
  prompt, messages, tool schema, `tool_choice`, `max_tokens`, `temperature`.
- A prompt's text never changes without its version constant in `config.py`.
- `--offline` never calls the API: a miss is an error. `test_pipeline.py`, in the
  pytest run CI makes, replays `run-all` and both evals offline and fails if a
  committed report differs from the regenerated one or an entry goes unread.
- Only transcripts whose resolved path is under `data/transcripts/` are recorded
  (invariant 5).

## Validate at trust boundaries

- **`weaknesses.yaml`:** the validation rules in brief §6.1; a bad file fails loading with
  the theme and field named.
- **Model tool output:** parsed into `Detection`s; a missing field, a value outside the
  enum or a confidence outside [0, 1] is a recorded rejection, not an exception.
- **CLI input:** the transcript path exists, is a `.txt` file and is under a size cap.

Fail loud on programmer error. Fail *recorded* on data error.

## Review checklist

Report every finding with a confidence and a severity, then rank. Skip what ruff and
pyright already enforce. In order:

1. **Invariants** 1–7.
2. **Boundaries:** empty transcript, a transcript with no `PROSPECT:` lines, two
   objections with the same theme, a quote with curly quotes or line breaks, a quote
   that spans speakers, an empty model answer, a theme removed from the YAML.
3. **Failure behavior:** API timeout, 429, malformed tool output, Slack 4xx/5xx,
   DuckDB file locked. Does `run-all` continue past one bad transcript and report it?
4. **The test:** is there one that fails if this logic breaks, with no network?
5. **Over-engineering:** anything to delete, inline, or replace with the stdlib?
